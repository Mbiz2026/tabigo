# アプリ修正の手順書(どのモデルもこの通りに実行する)

対象: `index.html`(トレーニング本体)、`diagnose.html`(診断)。
教材データだけを触る場合は本書ではなく `docs/add_content.md` を使う。

## 不可侵リスト(変更禁止。破るとユーザーの学習履歴が消える)

1. localStorage キー名: `tabigo-train-v1`(診断側は `tabigo-diag-v1`)
2. SRSカード状態のフィールド名: `ivl, due, ease, reps, lap, hist, stage`
3. 保存データのトップ構造: `profile, srs, log, owned, totalReviews`
4. 教材の既存ID(s01〜, c01〜, l01〜 …)
5. 本番URL(GitHub Pages。CLAUDE.md記載)とArtifact URL(移行前のみ・同URL再公開)
6. セクションマーカーコメント(`コンテンツバンク` / `状態管理` など)—
   検証スクリプトが位置特定に使っている
7. バックアップコードの形式: プレフィックス `TABIGO1.` + base64(JSON)。
   ユーザーが過去に控えたコードが将来のバージョンでも復元できること
   (importCode は古い形式を永久に受け付ける。形式を進化させる場合は
   TABIGO2. を追加し、TABIGO1. の読み込みは残す)
8. IndexedDB名: DB `tabigo` / ストア `kv`(localStorageとの二重保存に使用)

構造変更がどうしても必要な場合: キー名は変えず、読み込み時に旧形式を検出して
新形式に変換する移行コードを書く。下の「旧データでのテスト」を必ず実施。

## 設計原則チェックリスト(変更がこれに反していないか、公開前に全項目を自問する)

- [ ] 日数カウント(ストリーク)・連続記録を導入していないか
- [ ] サボりに対するペナルティ・喪失感の演出を入れていないか
- [ ] 可変時間メニュー(3/10/20分)を維持しているか。3分コースは復習のみのままか
- [ ] 「時間が来たらアプリ側から終了を促す」挙動を壊していないか
- [ ] 全カードの「出題理由」表示を維持しているか
- [ ] 21時以降=復習のみ、の挙動を維持しているか
- [ ] ホーム画面の主役が反射速度グラフのままか(バッジ・レベル等を主役にしない)
- [ ] 変動報酬の確率を大きく変えていないか(基準35%)
- [ ] ライト/ダーク両テーマで配色トークン(CSS変数)経由の色指定を守っているか
- [ ] 新しい設定項目・選択肢を増やしていないか(摩擦は継続の敵。増やすならユーザー承認)
- [ ] コース選択(ミックス/はなす/きく/ドライブ)を維持し、デフォルトがミックスのままか
- [ ] ドライブモードに画面注視・細かいタップを要する要素を追加していないか(運転中の安全)
- [ ] ドライブモードがSRSの記録(ivl/due等)に書き込んでいないか(自己採点が無いため測定を汚す)
- [ ] ドライブモードが「終了ボタンを押すまで連続再生」のままか(時間で勝手に止めない)
- [ ] 通常セッションが「選んだ時間まで教材を自動補充」する挙動のままか(早終わりしない)
- [ ] speakAsyncの番犬タイマーとdrive中のresume()蹴り起こしを外していないか(TTS固まり対策)

## デザイントークン(色はすべてCSS変数経由。直値をコンポーネントに書かない)

`--bg --card --ink --sub --line --accent --accent-ink --hl --ok --ok-bg --warn --warn-bg --gold --gold-bg`
ライト/ダークは `:root` + `@media(prefers-color-scheme)` + `:root[data-theme=...]` の
3段構成になっている。トークンの再定義のみ行い、コンポーネント側のスタイルは触らない。

## 修正の手順(この順番を変えない)

1. `CLAUDE.md` と本ファイルを最後まで読む
2. 修正内容がユーザーの依頼と一致しているか確認。依頼に無い「ついで改善」はしない
3. リポジトリ版を編集 → `<script>` 部を抽出して `node --check`
4. `node scripts/validate.mjs index.html` で ERROR 0件
5. **旧データでのテスト**(構造に触れた場合は必須):
   下のサンプルを localStorage に投入した状態を想定し、読み込み・グラフ描画・
   セッション開始がエラーなく通るかコードを追ってレビューする
   ```json
   {"profile":{"anchor":"朝のコーヒーを淹れたら","start":"2026-07-11","listenRate":0.87,"listenIdx":3,"shadowIdx":1,"onboarded":true},
    "srs":{"s01":{"ivl":2,"due":"2026-07-13","ease":2.02,"reps":2,"lap":0,"hist":[{"d":"2026-07-11","sec":3.8,"r":"good"}],"stage":0},
           "c13":{"ivl":1,"due":"2026-07-12","ease":2.0,"reps":1,"lap":1,"hist":[{"d":"2026-07-11","sec":null,"r":"again"}],"stage":1}},
    "log":[{"d":"2026-07-11","n":14,"medSec":4.2,"min":10}],
    "owned":["st1"],"totalReviews":15}
   ```
6. 手動スモークテスト項目(ブラウザ実行ができる環境なら実行、できなければ
   コードレビューで全経路を追う):
   - 初回オンボーディング(アンカー選択)→ホーム表示
   - 3分セッション: 瞬間英作文の ◎/△/✕ 各1回、✕カードの再出題
   - 10分セッション: チャンク認識(3択)→想起(めくり)、リスニング再生と速度増減
   - セッション終了画面: 中央値表示・ご褒美・ホームのグラフ更新
   - 21時以降を想定した復習のみモード
7. 「公開手順」(下記)に従って公開
8. ユーザーへ報告: 何が変わったか(1〜3行)+変わらないこと(学習データは無事、等)

## 公開手順(Pages移行後の正規手順)

1. `sw.js` の `CACHE = "tabigo-vN"` の N を1つ上げる(忘れるとユーザーに旧版が
   キャッシュから配られ続ける)
2. tabigo リポジトリの main にコミット・プッシュ → GitHub Pagesが自動配信
3. ユーザーへの案内は不要(次にアプリを開いたときに新版へ切り替わる)
4. Pages移行前にArtifactを更新する場合のみ: body専用形式に変換し、CLAUDE.mdの
   既存URLへ `url` 指定で再公開(このときmanifestリンクは含めない)

## 禁止事項

- 「より良い設計を思いついた」による無断リファクタリング・機能追加
- 外部ライブラリ・CDN・ビルドツールの導入(単一HTML・依存ゼロを維持)
- 診断(diagnose.html)の設問・採点基準の変更(定点観測が壊れる)。
  変更する場合はバージョン番号を付けた別ファイルにする
